# Bugfix Requirements Document

## Introduction

В файле `src/lib/templates/grade8/pythagoreanTheorem.ts` обнаружены баги в шаблонах задач по теореме Пифагора (`grade8PythagoreanTheoremTemplates`). Баги затрагивают шаблоны `grade8-pythag-hypotenuse`, `grade8-pythag-leg` и `grade8-pythag-distance`. Проблемы: отсутствующий `answer_type` на уровне 1 гипотенузы, сломанная интерполяция переменных в LaTeX-строках `solution`, некорректные `constraints` уровня 1 (допускают иррациональную гипотенузу), и потенциально некорректное форматирование поля `result`.

---

## Bug Analysis

### Current Behavior (Defect)

1.1 WHEN пользователь решает задачу `grade8-pythag-hypotenuse` уровня 1 с катетами, дающими иррациональную гипотенузу (например, a=5, b=8 → √89), THEN движок расценивает ответ как `number` (нет `answer_type: 'expression'`) и требует десятичную дробь вместо символьного выражения `sqrt(89)`

1.2 WHEN шаблонизатор обрабатывает строки `solution` вида `c = $\sqrt{a*a + b*b}$` (без двойных фигурных скобок), THEN переменные `a` и `b` не интерполируются и в UI выводится сырой LaTeX `\sqrt{a * a + b * b}` вместо вычисленного значения

1.3 WHEN генератор выбирает параметры для `grade8-pythag-hypotenuse` уровня 1 с ограничением только `a !== b`, THEN допускаются треугольники с иррациональной гипотенузой (например, a=5, b=8 → √89), хотя уровень 1 предназначен для целых ответов

1.4 WHEN поле `result` содержит строку `sqrt({a*a + b*b})` и модуль MathInput обрабатывает её, THEN возможен некорректный рендеринг в UI (сырой текст вместо красивого √89)

1.5 WHEN шаблонизатор обрабатывает строки `solution` в шаблонах `grade8-pythag-leg` и `grade8-pythag-distance` с аналогичным паттерном `$\sqrt{expr}$` без двойных фигурных скобок, THEN переменные не интерполируются и в UI выводится сырой LaTeX

### Expected Behavior (Correct)

2.1 WHEN пользователь решает задачу `grade8-pythag-hypotenuse` уровня 1, THEN движок SHALL корректно обрабатывать символьный ввод `sqrt(N)` благодаря наличию `answer_type: 'expression'` на этом уровне

2.2 WHEN шаблонизатор обрабатывает строки `solution` с выражениями внутри `\sqrt{}`, THEN система SHALL интерполировать переменные, используя двойные фигурные скобки `$\sqrt{{a*a + b*b}}$`, и выводить вычисленное значение (например, `$\sqrt{89}$`)

2.3 WHEN генератор выбирает параметры для `grade8-pythag-hypotenuse` уровня 1, THEN система SHALL применять ограничение `Math.sqrt(a*a + b*b) === Math.floor(Math.sqrt(a*a + b*b))` и гарантировать целочисленную гипотенузу (пифагоровы тройки)

2.4 WHEN поле `result` содержит строку `sqrt({a*a + b*b})` с интерполированным значением, THEN модуль MathInput SHALL рендерить красивый символ √89 в UI без сырого текста

2.5 WHEN шаблонизатор обрабатывает строки `solution` в шаблонах `grade8-pythag-leg` и `grade8-pythag-distance`, THEN система SHALL корректно интерполировать переменные внутри `\sqrt{}` через двойные фигурные скобки во всех уровнях сложности

### Unchanged Behavior (Regression Prevention)

3.1 WHEN пользователь решает задачу `grade8-pythag-hypotenuse` уровня 2 или 3 с иррациональной гипотенузой, THEN система SHALL CONTINUE TO принимать ответ в формате `sqrt(N)` через `answer_type: 'expression'`

3.2 WHEN пользователь решает задачу `grade8-pythag-leg` уровня 1 с целым ответом, THEN система SHALL CONTINUE TO корректно валидировать числовой ответ (существующий `constraints` с проверкой на целое число не меняется)

3.3 WHEN пользователь решает задачу `grade8-pythag-check` любого уровня, THEN система SHALL CONTINUE TO корректно обрабатывать текстовые ответы «да»/«нет» и числовые ответы (шаблон не затронут)

3.4 WHEN генератор создаёт задачи `grade8-pythag-distance` любого уровня, THEN система SHALL CONTINUE TO корректно вычислять расстояние между точками и принимать ответ в формате `sqrt(N)` через `answer_type: 'expression'`

3.5 WHEN шаблонизатор обрабатывает строки `hint` без LaTeX-команд (например, `'Гипотенуза² = катет₁² + катет₂²'`), THEN система SHALL CONTINUE TO выводить их как обычный текст без изменений
